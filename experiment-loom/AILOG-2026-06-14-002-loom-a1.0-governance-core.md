# AILOG: Loom A1.0 — governance primitives → straymark-core

## Summary

Executed track **A1.0** of `CHARTER-01-loom-server` (Architecture Plan view, Spec 002,
`ADR-2026-06-02-002`): the M0-style de-risking move that relocates the governance-state
extraction primitives the "you are here" status projection depends on — Charter parsing and
the drift wildcard matcher — out of `cli/` into the shared `straymark-core` crate. This makes
the projection's inputs **core-computable**, so the future Loom server (A2, which depends on
`core` not `cli`) and the CLI share exactly one extractor. **Zero behavior change**, verified
against the declared regression oracle (full workspace test suite + the existing
`charter`/`audit`/`drift`/`validate` integration suites, all byte-for-byte green).

## Context

Spec 002 §4 requires the status projection to be a **pure function in `straymark-core`** so
the CLI can answer "where are we" textually (`straymark status --where`, A1.4) and the Loom
server can render it (A2). Its inputs — active/closed Charter declared files, declared∩modified
drift — were parsed only in `cli/`. A1.0 moves those primitives to `core` first (its own
bisectable PR, mirroring M0's `document.rs` extraction), de-risking the refactor before any
architecture code exists and structurally mitigating plan §8 **R5** ("one parser, no drift").

Scope was deliberately trimmed from the ex-ante `tasks.md` after reading the code (recorded in
that file): `ailog.rs` is **not** moved (the drift primitives don't depend on it, and the
projection's AILOG "Modified Files" parser is new code that belongs in A1.1), and **no
`glob`/`regex` dep** is added to `core` yet (the drift matchers are custom string functions;
`glob` lands in A1.1 when the projection matches component globs to file paths).

## Decisions Made

- **`ailog.rs` not moved in A1.0** (scope refinement vs ex-ante T0.3): the drift primitives
  are pure and don't depend on it; the projection's AILOG "Modified Files" parser is *new*
  code authored in A1.1. Moving `ailog.rs` now would churn A1.0 for no A1.0 benefit and risk
  moving it twice. Recorded in `tasks.md` T0.3.
- **No `glob`/`regex` dep added to `core` in A1.0** (vs ex-ante T0.4): the drift wildcard
  matcher is a custom string function (mirrors the bash `check-charter-drift.sh` semantics),
  no crate needed. `glob` is added in A1.1 when the projection matches component globs.
- **No standalone release** (vs M0, which published core): A1.0 has zero user-visible value
  and `straymark-core` 0.4.1 is still unpublished, so the `core` minor bump + `cli` minor
  bump + crates.io publish + tag all ride the **A1.5** `cli-` release. A1.0 merges as its own
  PR so A1.1 branches fresh from `main` (no stacked-PR-on-squash hazard, CLAUDE.md §Git).
