# AILOG: Loom A1.5 — Architecture Plan track A1 closed

## Summary

Closed track **A1** of `CHARTER-01-loom-server` (Architecture Plan view, Spec 002,
`ADR-2026-06-02-002`): the textual + authoring half of Loom's "you are here" map, shipped
ahead of the visual overlay (A2). A1.5 is the track's **single release** — it dogfoods the
generator on this repo, records the spec §11 (A1 subset) acceptance, ships the user docs in
EN/ES/zh-CN, and performs the one version bump that covers A1.0–A1.4 (which all merged tagless
by design): **`straymark-core` 0.4.1 → 0.5.0** (new `architecture` module surface) and
**`straymark-cli` 3.24.0 → 3.25.0** (the `architecture` command + `status --where`). The
crates.io publish of `straymark-core` rides the `cli-3.25.0` release per the M0 decision.

projection give a terminal "where are we?" before any new pixels (A2 renders the same model in

## Decisions Made

- **Dogfood home is `experimento/architecture/`, not `.straymark/architecture/`** — this repo
  is not an adopter of itself (no root `.straymark/`), so `--out` points the artifacts where the
  Loom dev tree already lives. The adopter default is unchanged.
- **Component ids frozen during refinement.** The refinement reassigned layers, renamed labels,
  and added links, but never renamed a component `id` — ids are the stable cross-reference to
  `plan.drawio` cells, so `architecture validate` stays at exit 0 (no `undrawn`/`unmodeled`).
- **`core` dependency pins bumped in all dependents.** A `core` minor bump forces
  `cli/Cargo.toml` and `experimento/Cargo.toml` to move their `version = "0.4.1"` reqs to
  `0.5.0` or the workspace path-dep resolution fails; loom recompiles against 0.5.0 without a
  loom release (its `loom-*` cycle is independent).
- **Combined `## CLI 3.25.0 / Core 0.5.0` changelog heading** (per CLAUDE.md's "combine when
  both bump together"), with `### Added (Core)` documenting the new public `architecture`
  surface for crates.io consumers.

## Impact

- **Functionality**: new EXPERIMENTAL `straymark architecture <generate|sync|validate>` and
  `straymark status --where`; no change to any existing command.
- **API (core)**: `straymark-core` 0.5.0 adds the public `architecture` module + `ailog`
  parser — additive, backward compatible (minor bump).
- **Performance / Security / Privacy**: N/A (parse + render only; no new I/O or network surface;
  `status --where` and `validate` are read-only).
