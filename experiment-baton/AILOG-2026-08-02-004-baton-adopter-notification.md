# AILOG: Baton Track C — adopters are now notified (docs + direct push)

## Summary

Closes the last delivery gap in Track C. The adopter kit (07) existed, the
binary channel (release-baton.yml, 0.2.0) existed, but nothing *told* an
adopter either thing existed. This change builds the notification stack,
mirroring how Loom was introduced to adopters (own guide page + WORKFLOWS
pointer ×3 locales) and adding the direct-push piece Loom didn't need: a
ready-to-post Adopters Discussion, because Track C is an active request, not
a passive feature.

## What changed

- **`docs/adopters/BATON.md` (+ es, zh-CN mirrors)** — the durable destination.
  EXPERIMENTAL banner; what Baton is and the declaration-based classification
  turn (#332); what Track C asks (declare `work_verb`, work as usual,
  simplified calibration after 2–4 weeks); **how to get the binary** —
  platform asset table for the `baton-*` release plus compile-from-source;
  read-only guarantees; honest limitations (releases replace each other while
  in Track C). Commands verified against `experiment-baton/src/main.rs`
  (`classify`, `route --dry-run` — there is no `scan` subcommand; caught and
  corrected during drafting).
- **`WORKFLOWS.md` ×3** — a "Declared work routing (Baton, experimental)"
  subsection next to the existing Loom one, with the two sanity commands and
  a link into BATON.md.
- **`08-track-c-adopter-announcement-draft.md`** — ready-to-post Discussion
  (Adopters category): what changed, what's asked, what's explicitly NOT
  asked, doc links. Includes posting preconditions (after the release-channel
  PR merges and `baton-0.2.0` is cut).

## Website

No website change needed: the docs plugin includes `adopters/**` and the
sidebar is autogenerated from that directory — BATON.md appears automatically
on next site build.

## Verification

Every command quoted in the new docs checked against the actual clap
subcommand definitions (`inspect`, `intent`, `coherence`, `overlay`,
`classify`, `route`). Asset naming checked against release-baton.yml.
Link targets verified to exist (kit, ADOPTER-FEEDBACK, CLI-REFERENCE).
